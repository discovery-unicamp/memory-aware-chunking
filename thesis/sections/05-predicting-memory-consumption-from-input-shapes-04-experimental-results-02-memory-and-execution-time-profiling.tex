\subsection{Memory and Execution-Time Profiling}
\label{subsec:pmc-results-memory-and-execution-time-profiling}

This section examines raw memory and execution-time measurements.
The goal is to understand how input shape influences resource demand before applying predictive modeling.
While full feature selection results are discussed later (Section~\ref{subsec:pmc-results-feature-selection-experiments}), the apparent dominance of the \emph{volume} feature\textemdash defined as $\text{inlines} \times \text{xlines} \times \text{samples}$\textemdash motivates its early focus in the analysis.

\subsubsection{Linear Trends and Variability}
\label{subsec:linear-trends-and-variability}

Figure~\ref{fig:peak_memory_facet} illustrates that peak memory usage scales approximately linearly with volume.
The Envelope, \ac{GST3D}, and Gaussian Filter operators exhibit similar growth patterns, albeit with different slopes and variabilities.
Larger volumes lead to more consistent memory consumption, whereas smaller volumes show higher \ac{CV} due to overhead fluctuations such as interpreter startup or \ac{I/O} buffering.

\subsubsection{Memory Safety Margins and Aspect Analysis}
\label{subsec:memory-safety-margins}

Figure~\ref{fig:memory_safety_margin} shows a substantial gap between the average memory usage and the 95\% percentile for Envelope, \ac{GST3D}, and Gaussian Filter.
Two possible causes explain this discrepancy:
(1) different shapes that map to the same volume (\eg, $100$ $\times$ $300$ $\times$ $200$ vs. $300$ $\times$ $100$ $\times$ $200$) may exhibit distinct memory consumption, or
(2) early experiment runs may incur higher overhead, as discussed in Chapter~\ref{ch:measuring-memory-consumption}.

Initialization overheads and shape‐induced variability produce wider margins at smaller volumes, which tighten as data size grows.}

To investigate whether varying shape dimensions (while fixing the same total volume) leads to significant memory differences, Figure~\ref{fig:memory_by_volume_aspect} bins each operator's memory usage by volume and aspect-ratio ranges.
The aspect ratio
\[
    \text{Aspect} \;=\; \frac{\text{inlines}}{\text{xlines}}
\]
is grouped into intervals (\textless0.5, 0.5--1, 1--2, 2--5, \textgreater5).
The boxplots reveal no pronounced sensitivity to aspect-ratio changes: curves in each volume bin overlap substantially, regardless of whether the shape is long, narrow, or nearly cubic.
Consequently, shape permutations at a fixed volume do not appear to cause a significant jump from the average to the 95\% percentile.

These observations indicate that overhead in the earliest runs is the most likely explanation for high outlier memory usage.
In other words, most runs stay near the mean, while specific initial sessions consume disproportionately more memory due to initialization overhead or caching.
The spikes in Figure~\ref{fig:memory_safety_margin} thus represent comparatively rare events that can inflate the 95\% percentile above the mean.
