\section{Related Work}
\label{sec:related-work}

Memory management in high-performance computing (HPC) has evolved from simple static allocation to sophisticated predictive and adaptive techniques.
The challenge of balancing memory efficiency with computational performance has driven research across multiple dimensions: predictive modeling at various granularities, runtime adaptation mechanisms, and intelligent data partitioning strategies.
This section provides a comprehensive survey of these approaches, highlighting their strengths and limitations while positioning our memory-aware chunking method within the broader landscape of distributed computing optimization.

\subsection{Memory Prediction}

Memory prediction in HPC systems has traditionally operated at the job level, leveraging historical execution logs to estimate resource requirements.
Rodrigues et al.~\cite{rodrigues2016} pioneered machine learning approaches for HPC memory prediction, achieving 98\% classification accuracy using features such as user ID, requested processor count, and job queue information.
Their random forest models successfully categorized jobs into memory usage bins, enabling better scheduling decisions on IBM Blue Gene/Q systems.

Li et al.~\cite{li2019} extended this work by combining binary classification with specialized regression models for outlier cases.
Their two-stage approach first identifies whether a job will be memory-intensive, then applies targeted regressors trained on similar historical jobs.
While effective for recurring workloads, both approaches share fundamental limitations: they require extensive historical data, cannot adapt to new application types, and operate at too coarse a granularity to guide array-level memory management.

More recent work by Tanash et al.~\cite{tanash2021ampro} incorporates deep learning techniques, using LSTM networks to capture temporal patterns in job submission sequences.
However, the black-box nature of these models makes them unsuitable for the transparent, operator-specific predictions required in scientific computing contexts.

\subsection{Memory-Aware Scheduling}

Runtime memory adaptation represents an orthogonal approach to static prediction, focusing on dynamic response to memory pressure rather than upfront planning.
Cleo~\cite{khandelwal2020} implements cost-aware task migration for MapReduce workloads, monitoring memory usage across nodes and preemptively moving tasks before OOM conditions arise.
The system achieves 40\% reduction in job completion times by balancing memory load across the cluster.

Mary and its variants~\cite{thamsen2017} take a learning-based approach to runtime adaptation, building online models of task memory consumption and adjusting resource allocation dynamically.
The Hugo* variant specifically targets heterogeneous clusters, adapting its scheduling decisions based on node-specific memory characteristics.
These systems demonstrate the value of runtime monitoring but operate at container or task granularity, too coarse for the array-level chunking decisions required in numerical computing.

Myung and Lee~\cite{myung2021} propose memory harvesting techniques that reclaim unused memory from over-provisioned VMs.
While effective in cloud environments, this approach assumes elastic infrastructure unavailable in many HPC settings.
Fundamentally, these runtime systems complement rather than replace intelligent chunking: even perfect task migration cannot salvage a job where individual chunks exceed available memory.

\subsection{Chunking Techniques}

Data chunking strategies have evolved from simple uniform partitioning to sophisticated adaptive approaches, though most focus on I/O optimization rather than memory management.
Zhang et al.~\cite{zhang2019} developed an adaptive chunking system for HDF5 that optimizes storage layout based on access patterns, achieving 3× speedup for certain query workloads.
Their cost model considers disk seek times and compression ratios but does not account for in-memory processing requirements.

Tantisiriroj et al.~\cite{tantisiriroj2011} analyzed the duality between HDFS and PVFS chunking strategies, demonstrating that optimal chunk sizes depend heavily on workload characteristics.
Their empirical study revealed that the common 64MB default chunk size often leads to poor performance, motivating workload-specific tuning.
However, their analysis focuses exclusively on I/O throughput rather than memory consumption during computation.

Dask's current auto-chunking implementation~\cite{rocklin2015dask} represents the state-of-the-art in production systems.
The heuristic targets a fixed 128MB chunk size, attempting to balance scheduling overhead with memory usage.
While simple and often effective, this approach has critical limitations: it ignores operator-specific memory expansion, assumes uniform memory availability across workers, and provides no safety guarantees against OOM failures.
Our experiments show this leads to failure rates exceeding 30\% for memory-intensive operators.

\subsection{Performance Modelling}

Performance modeling in scientific computing has traditionally focused on execution time prediction, with memory treated as a secondary concern.
Carrington et al.~\cite{carrington2006} developed comprehensive performance models for HPC applications using hardware counters and application signatures.
Their convolution-based approach accurately predicts runtime across different architectures but provides only aggregate memory bandwidth metrics rather than peak usage predictions.

The NumPy ecosystem~\cite{harris2020} has inspired performance models specific to array computations.
These models typically focus on vectorization efficiency and cache behavior, useful for optimization but insufficient for distributed memory management.
Recent work has begun incorporating memory hierarchy effects, but stops short of predicting total memory footprint for complex operators.

Bhimji et al.~\cite{bhimji2016} examined I/O and memory interactions in the context of burst buffers, demonstrating that memory pressure significantly impacts overall application performance.
Their findings motivate our work: even small reductions in peak memory usage can enable dramatic improvements in system throughput by avoiding swap usage and OOM failures.

The gap in memory-specific modeling is particularly acute for domain-specific operators.
While general matrix operations have well-understood memory requirements, specialized kernels like seismic imaging operators exhibit complex, input-dependent allocation patterns.
Our contribution addresses this gap directly, showing that simple linear models can capture these patterns with sufficient accuracy for practical chunk size selection.
